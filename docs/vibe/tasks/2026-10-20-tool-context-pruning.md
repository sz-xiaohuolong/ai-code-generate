# 系统优化：工具调用上下文裁剪

本次优化只精简发送给 Vue 工具模型的上下文，不删除实际文件、正式聊天记录或前端展示代码。目标是减少已成功执行的历史写入参数、重复读取结果和旧任务写文件展示正文的重复传输；不把上下文裁剪等同于已经解决模型循环。

- 范围类型：Bounded；冻结意图为上段目标，沿用现有两种生成模式与 Vue 修复链路。
- 基线：`aa53a4d`；已有路由回退、原生代码完整性和推理配置等未提交改动保留，不混入本次提交。
- 需求状态：FROZEN；阻塞产品问题：无。实现与验证状态由 [PROGRESS](../PROGRESS.md) 维护。
- 发布授权：提交并同步 `origin/main`；不创建 PR、Tag，不部署，不调用真实付费模型作测试。

## 1. 现状与影响边界

`FileWriteTool.writeFile` 返回的已经是简短成功文本。代码全文主要在 `ToolExecutionRequest.arguments.content`；`modifyFile` 的旧、新正文同理。`FileReadTool` 返回文件全文。

LangChain4j 1.15.0 会把工具请求与结果一起放回记忆。任务生成和 Vue 修复使用独立临时记忆，不能仅修改 `DatabaseLoadingChatMemoryStore`。`TaskHistoryRecorder` 保存的最终展示文本也可能带有完整写文件代码，并被下个任务载入。

允许修改：新增 `ai/ToolContextPruner.java` 和对应测试；在 `AiCodeGeneratorServiceFactory` 的 Vue 服务构建处接入；补充 Vue 提示词；局部更新架构、进度及文档地图。文件工具、任务记录器、Redis 数据结构、公开 API、鉴权和前端协议保持不变。

不包含：修改 HTML／多文件模型链路、全量摘要、额外模型调用、新增重复调用熔断器、读取范围 API、模型版本调整和历史数据迁移。现有工具轮数、总时限、取消、文件沙箱与构建修复上限继续生效。

## 2. 方案与关键取舍

复用 Java 21、现有 JSON 库和 LangChain4j 1.15.0，不新增依赖。采用无共享可变状态的请求转换器，接入 `AiServices.chatRequestTransformer`；框架首次流式请求和每次工具续调都会经过该入口。标准 Vue、工作流 Vue 和 Vue 修复共用同一工厂，统一覆盖。

转换器只复制并投影 `ChatRequest.messages`，保留请求参数与工具定义，禁止原地修改记忆。真实工具先用完整参数执行，执行回调继续拿到完整正文供展示与存储；仅下一次发给模型的请求副本使用精简内容。

选择请求投影而非直接删除 Redis 历史，是为了覆盖临时记忆并保留展示和追溯。代价是原始记忆、数据库与前端数据量不因此下降，且裁剪不能消除模型生成正文本身的输出 Token。

### 2.1 裁剪规则

1. **识别完整工具组**：一条 AI 消息中的工具调用必须拥有非空且唯一的 ID，且后续连续工具结果与调用 ID、名称一一对应。缺结果、多结果、错配或重复 ID 时整组保持原样，不修复或掩盖协议错误。
2. **已成功写入**：只接受项目现有明确成功回执，且框架错误标记不是 `true`。当 `content` 超过 1024 个字符时，在历史参数副本中换成明确的“正文已省略”字符串；结果副本变为 JSON，包含工具名、相对路径、`status=success`、行数、字符数、SHA-256 和 `contentOmitted=true`。
3. **已成功修改**：同样只处理明确成功回执。只省略超过上述阈值的 `oldContent`／`newContent`；回执说明省略的是补丁正文，并记录对应字段的字符数和哈希，不把补丁哈希冒充当前文件哈希。
4. **历史读取**：对同一路径保留最新一次成功读取的完整正文；仅将更早的大段成功读取结果替换为路径、行数、字符数和内容哈希的 JSON 摘要。读取错误、唯一一次读取、不同文件的最新读取均保留。摘要带 `contextPruned=true` 保留标记，二次投影时不将摘要当源码或最新完整读取；即使原文件 JSON 恰好包含相同回执标记，也保守保留而不继续裁剪。
5. **旧任务写入展示**：只识别 AI 文本中项目写文件展示器输出的完整 `[工具调用] 写入文件 路径` 加代码围栏结构，压缩其中超过阈值的代码；保留周围解释。回执标记为 `status=recorded`，因为展示器即使写入失败也可能展示调用参数，不能用展示记录证明成功。先核对整条 AI 文本中的围栏是否全部属于已识别展示块，出现额外围栏、普通代码示例或嵌套歧义时整条保留，不把正文中的工具标记作为可信边界。用户消息、未知语言和不完整格式不裁剪；元数据排除展示器额外添加的分隔换行。
6. **小正文不裁剪**：1024 为内部字符阈值，用于避免元数据比短正文更长，不是 Token 窗口或模型容量承诺。转换后的同一请求再次处理应保持不变。

行数按文本行计算，结尾换行不额外制造一行；摘要的哈希和行数描述该次操作时的内容快照，不承诺文件以后未被修改。只知道执行成功，不代表构建通过。

### 2.2 协议与错误边界

- 保留 AI 消息的文本、`thinking`、属性及全部工具调用 ID／名称；仅复制待裁剪的正文参数。DeepSeek 的推理回传要求保持不变。
- 保留工具结果的 ID、名称、错误标记和属性；多模态结果、未知工具、无法解析的参数与不明确成功结果原样传递。
- 参数解析只作用于完成调用的历史副本，不改变待执行参数和工具 Schema；不允许将摘要重新作为工具输入执行。
- 转换器不读文件、不操作数据库或 Redis，不增加重试、异步状态和取消资源；失败和取消仍由原有执行链处理。
- 不记录代码、用户正文或密钥；调试日志只允许消息数量及裁剪前后的正文字符数。字符量下降不能冒充实际 Token、耗时或费用下降。

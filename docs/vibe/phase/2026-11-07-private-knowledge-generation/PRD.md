# 产品需求文档：个人知识库辅助代码生成

用户上传自己的内部文档，在发送生成需求时选择是否使用个人知识库。启用后，平台从该用户全部可用资料中按语义检索相关内容，辅助生成代码并展示参考资料。首期每个用户只有一个个人知识库，不增加文档选择或独立知识问答入口。

## 1. 产品概述与背景

平台已有自然语言生成、应用工作台、标准／工作流两种生成模式，以及 HTML／多文件／Vue 三种代码类型。本次增加可复用的个人资料来源，使用户能够依据自己的接口说明、业务规范和个人资料生成前端应用，无需每轮手工粘贴全部文档。

文件上传解决资料进入平台的问题；本功能进一步解决资料的持续管理、用户隔离、按当前需求检索相关片段，以及生成依据的核对问题。检索范围是个人库全部可用文档，实际提供给模型的是相关片段，并非每次发送所有文件全文。

本次成功定义：用户能管理私有资料、按次选择是否使用，并看到实际提供给模型的参考资料；其他用户不能通过资料或来源入口读取这些内容。生成代码是否正确遵循资料须独立验收，不能以“检索有结果”代替质量验证。

产品定位沿用 [PRODUCT.md](../../../../PRODUCT.md)。本功能服务于平台生成代码的过程，不要求生成的网站自带 RAG 或知识问答能力。

## 2. 目标与非目标

- **个人私有资料**：每个登录用户一个个人知识库，跨自己的应用复用，其他用户不可读取。
- **按需检索**：开启后从全部可用资料中语义检索，不提供文档勾选或多个知识库管理。
- **按次启用**：输入框默认关闭；发送后固定本次选择，生成及既有自动修复沿用同次资料上下文。
- **可管理、可核对**：支持上传、列表、状态、替换、失败重试、删除，并能核对历史生成任务的参考资料。
- **首期排除**：共享／公共知识库、组织权限、PDF／Word／OCR、网页抓取、独立知识问答页面、多向量数据库、混合检索、重排，以及额外的文档冲突检测或裁决。
- **不作效果承诺**：不预设生成质量提升比例、处理时延或成本下降；以固定样本与实际运行证据判断。

## 3. 目标用户与使用场景

| 用户 | 权限与诉求 | 典型场景 |
|---|---|---|
| 登录用户 | 管理并使用自己的资料 | 上传 Markdown 接口说明，开启知识库生成订单页面 |
| 同一用户的多个应用 | 复用同一个人资料库 | 为不同应用提出需求，由语义检索选择相关片段 |
| 不使用知识库的用户 | 继续普通生成 | 关闭开关，不新增本次知识检索 |
| 核对历史生成的应用所有者 | 查看当时提供给模型的资料 | 对照文档版本、片段与生成代码，定位接口字段不一致的问题 |

用户需在需求中表达清楚项目和业务语境。独立文档可能含有矛盾内容；首期不保证识别或裁决所有冲突。用户可查看参考片段后整理资料，或显式替换过时文档。

## 5. 核心功能与验收

### 5.1 REQ-01：个人资料与用户隔离

每个用户仅管理自己的一个个人知识库。上传、列表、读取内容、替换、重试、删除、检索和参考资料查询均受所有权约束。身份以服务端验证的登录用户为准，不接受请求参数、提示词或文档正文扩大权限；管理员身份不自动取得其他用户的资料读取权限。

“个人知识库”表示用户的资料范围，不要求每个用户运行独立数据库实例。Chroma 的数据分区不能代替应用服务端鉴权。两个用户上传相同内容时，任一用户的替换或删除不得影响另一用户。

| AC | 给定—当—则 | 检查入口 |
|---|---|---|
| AC-01 | 给定 A、B 两个用户及各自私有文档，当 B 或非所有者管理员尝试访问或修改 A 的资料、版本及任务参考记录，则服务端拒绝，且不返回正文、名称或片段 | 登录态、管理／检索／来源接口 |
| AC-02 | 给定 A 的文档含独有标记，当 B 用相近语义提问或篡改请求中的用户／资料标识，则 B 的模型上下文不得包含 A 的标记 | 双用户夹具、请求篡改、模型请求探针 |
| AC-03 | 给定 A、B 上传相同文件，当 A 替换或删除自己的文档，则 B 的文档和检索结果不受影响 | 相同内容夹具、双用户管理与检索 |

### 5.2 REQ-02：上传、版本与删除

新增“我的知识库”管理页，支持 Markdown／TXT 上传、资料列表、处理状态、显式替换、失败重试与删除。上传完成不等于可检索；只有处理成功的完整版本可进入检索。无可提取文字或无法处理的文件应明确失败，不伪装成可用文档。

显式替换产生新版本。新版本处理完成前，旧版继续可用；成功后，新任务使用新版，旧版退出新任务检索。替换失败不损坏旧版，用户可重试。同名新上传视为独立文档，不自动覆盖；首期不提供历史版本回滚或批量版本管理。

用户删除文档后，立即阻止新任务取得该文档。删除前已取得资料快照的任务可使用该快照完成；已删除文档的历史参考记录保留名称、版本，但不再向用户展示原文片段。清理失败可重试，不能恢复可检索或可查看状态；迟到的处理回调不能让文档重新出现。已有代码与聊天中已经包含的内容不自动抹除，删除确认应说明这一边界。

首期限额可配置，默认单文件 **2 MiB**、每用户 **50 份文档**、当前文档总量 **20 MiB**，1 MiB = 1,048,576 字节。上传前展示限制，服务端再次校验，超限明确拒绝，不截断文件。数量按未删除的文档计，含处理中和失败条目；同一文档的替换不增加文档份数。总量按当前文档文件大小统计，替换按成功切换后的预计总量校验，处理中上传须预占额度以防并发越限。旧版本快照不作为当前文档重复计入，长期参考记录的实际存储量需另行观测。

| AC | 给定—当—则 | 检查入口 |
|---|---|---|
| AC-04 | 给定有效 Markdown／TXT，当上传并成功处理，则列表显示可用且进入该用户检索范围；处理中或失败版本不得提前可用 | 上传、状态、检索 |
| AC-05 | 给定不支持的文件、无可提取文字或处理故障，当上传处理，则明确拒绝或显示失败；对可重试故障重试后可恢复，不生成重复可用版本 | 文件及故障夹具、重试入口 |
| AC-06 | 给定可用旧版，当替换处理中或失败，则旧版仍可检索；新版成功后新任务只使用新版；同名新上传不覆盖旧文档 | 版本切换、失败及同名夹具 |
| AC-07 | 给定文档正在处理或任务正在取得资料，当删除，则删除生效后新任务不能取得该文档，迟到回调和清理失败不能恢复可见性；删除前已取得快照的任务可完成 | 可控并发、删除、处理回调、检索 |
| AC-08 | 给定大小、数量或总量处于限额边界，当上传或替换，则等于限额可接受，超限明确拒绝；并发请求不能绕过额度，替换失败不损坏旧版 | 字节边界、50 份边界、并发上传 |

### 5.3 REQ-03：本次生成使用知识库

首页创建输入框与工作台输入框均提供“使用知识库”开关和管理入口，覆盖标准／工作流两种模式与 HTML／多文件／Vue 三种代码类型。首页选择须传递给该次初始生成任务；已有客户端未传选择时按关闭处理。

进入页面默认关闭。同一页面连续对话沿用当前开关；刷新、重新进入或切换应用后恢复关闭，不按应用长期保存。用户发送前可调整，发送后固定本次任务的选择。

启用后，从当前用户全部可用资料按语义检索相关片段。任务取得资料后固定当次版本与片段，生成、既有自动重生成及自动修复沿用该上下文，不因后续替换文档或修改开关改用另一份资料。新一次用户提交可重新检索。

关闭表示本次不新增知识检索，不保证已有代码、历史聊天或模型上下文中不再包含过去使用的资料。任务取消、超时、幂等与已有成功版本保护继续沿用现有规则。

| AC | 给定—当—则 | 检查入口 |
|---|---|---|
| AC-09 | 给定首页或工作台选择开启，当在两模式、三类型组合下生成，则该次任务按选择检索并将相关片段提供给生成模型；无需选择文档 | 两入口、六种组合、模型请求 |
| AC-10 | 给定选择关闭或旧客户端未传选择，当发送，则不调用知识检索且沿用普通生成；刷新、切换应用或重新进入默认关闭，同页连续发送沿用当前选择 | UI 状态、兼容请求、检索探针 |
| AC-11 | 给定任务已取得参考片段，当自动重生成／修复期间修改开关、替换或删除文档，则任务沿用当次快照；下一次提交使用当时仍有效的资料版本 | 重生成与修复夹具、版本与删除竞态 |

### 5.4 REQ-04：缺少依据与依赖故障

开启知识库后，没有可用文档、没有相关命中和检索依赖故障分别说明原因，停止本次生成，不静默降级普通生成。用户可补充资料、修复依赖，或关闭开关后重新提交。失败不得覆盖已有成功代码。

文档处理时 Ollama 不可用应明确呈现处理失败；生成时查询向量化或 Chroma 检索失败应明确呈现检索故障，不能冒充“没有相关资料”。不静默切换为外部 Embedding 服务。

相关性阈值、分块和片段预算留待技术验证；需覆盖中文需求和中文文档。超过模型上下文容量应通过合理分块与有界检索处理，不能把静默截断后的文档标记为完整处理。

| AC | 给定—当—则 | 检查入口 |
|---|---|---|
| AC-12 | 给定空库、全部处理中或确无相关内容，当启用知识库发送，则分别说明无可用资料或无相关结果，不进入代码生成模型调用 | 空库、无命中固定样本、调用探针 |
| AC-13 | 给定 Ollama 或 Chroma 不可用，当处理文档或执行检索，则对应操作明确失败，不回退云端 Embedding 或普通生成，不覆盖旧成功产物 | 依赖故障注入、网络调用与产物检查 |

### 5.5 REQ-05：参考资料与保留规则

生成任务记录旁展示“参考资料”，包含实际提供给模型的文档名称、当时版本及相关片段。它记录模型收到的依据，不从模型自述推断引用，也不表示模型已正确遵循资料。只有检索候选、尚未实际提供模型的内容，不能标记为已使用的参考资料。

参考资料记录**长期保留，随所属应用删除**。旧文档被替换后，历史任务仍展示当时版本的片段，不拿最新版冒充历史输入。用户主动删除知识文档后，历史记录保留名称、版本并提示“文档已删除”，原文片段不再展示。已按 Q8 允许继续运行的任务也遵守此展示限制。

三类数据的生命周期如下：

| 数据 | 保留与删除规则 |
|---|---|
| 个人知识库文档 | 保留到用户主动删除；删除某个应用不会删除个人知识库 |
| 任务参考资料记录 | 长期保留；所属应用删除后立即不可查询并清理；知识文档删除时保留名称、版本，隐藏原文片段 |
| 生成过程追踪 | 沿用既有追踪阶段的 7 天规则；追踪过期不导致任务参考资料过期 |

参考资料须有独立于短期任务快照和追踪的查询入口。应用删除后的物理清理可重试，但延迟和迟到写入不能恢复查询。参考资料读取或记录异常需如实提示不可用／不完整，不由模型或当前文档补造历史。

| AC | 给定—当—则 | 检查入口 |
|---|---|---|
| AC-14 | 给定资料已提供给生成模型，当查看参考资料，则名称、版本及片段与当次实际输入一致；候选内容或记录缺失不得伪装为实际参考 | 模型请求探针、来源记录与显示 |
| AC-15 | 给定文档已替换且任务追踪超过 7 天，当查看历史任务参考资料，则仍可查看当时版本与片段；不依赖 24 小时任务快照仍存在 | 可控时间、版本替换、历史查询 |
| AC-16 | 给定文档已删除，当查询所有历史或随后完成任务的来源，则只保留名称、版本及已删除提示，接口也不返回原文片段；已有聊天与代码不自动清除 | 删除、来源接口、运行中任务 |
| AC-17 | 给定应用已删除，当直接查询其参考记录，则立即拒绝；清理失败或迟到写入不能恢复查询，而该用户个人库仍可供其他应用使用 | 应用删除、直接编号查询、清理故障 |

### 5.6 REQ-06：数据处理边界与质量核对

Embedding 优先且直接使用本机 Ollama 已安装模型，生成模型沿用现有配置。管理页及使用入口应说明：文档由本地模型向量化；启用知识库时，检索片段会发送给配置的代码生成模型，若生成模型是外部服务，相应片段仍会发送到外部。“本地 Embedding”不等于全部资料处理全本地。

独立文档间冲突不新增专门检测或裁决流程。显式替换使旧版退出新任务检索；其他冲突由用户结合参考片段整理。界面提示生成结果需要核对，不承诺发现所有矛盾。资料正文作为参考数据，不能获得系统指令优先级、其他用户访问权或额外工具权限。

验收应准备非敏感的固定中文资料与需求，至少覆盖接口端点、请求／响应字段、业务规则、无关资料、版本替换和双用户隔离。工程回归验证数据与权限链路；真实模型验收须核对生成代码和页面行为，不把受控模型结果当作真实生成质量提升。

| AC | 给定—当—则 | 检查入口 |
|---|---|---|
| AC-18 | 给定本地 Embedding 与外部生成模型配置，当用户上传并开启知识库，则入口明确说明资料流向，实际调用与声明一致，不静默改用外部向量化服务 | 配置、UI 提示、网络调用 |
| AC-19 | 给定固定中文接口说明及非敏感模拟接口，当真实模型生成页面，则核对端点、字段与业务规则对应的请求和交互，并记录实际通过或失败；模型配置、样本与产物可追溯 | 固定样本、源码、模拟接口、浏览器行为 |
| AC-20 | 给定相互矛盾的独立文档或含越权指令的正文，当生成，则不宣称已自动解决全部冲突，也不因资料内容扩大权限；替换过时文档后，新任务不再检索旧版 | 冲突与注入夹具、来源及权限检查 |

## 6. 交互与界面状态

| 入口 | 空状态 | 加载状态 | 错误状态 | 边界状态 |
|---|---|---|---|---|
| 我的知识库 | 无文档，显示格式与限额并引导上传 | 区分上传、处理与替换；替换中说明旧版可用 | 说明失败原因，提供适用的重试操作 | 超限拒绝；删除确认说明历史和运行中任务影响 |
| 首页／工作台输入框 | 默认关闭，提供管理入口 | 显示检索阶段，运行中任务选择固定 | 区分无资料、无命中和依赖故障 | 同页沿用选择；刷新／切换应用重置关闭 |
| 任务参考资料 | 未使用知识库或未向模型提供资料时如实说明 | 不提前宣称已使用资料 | 记录缺失或读取失败显示不可用，不伪造来源 | 长片段可展开；已删除文档隐藏片段，旧版本明确标识 |

长内容按文本安全展示，不执行 Markdown／文档中嵌入的脚本。具体页面布局、分页和可访问性细节在设计阶段沿用平台规范。

## 7. 限制条件与跨功能边界

- 首期采用 Chroma，沿用 Java／LangChain4j 主线，不整体搬入 PaiSmart 的 Elasticsearch、Kafka、MinIO、账号、组织或聊天体系。可借鉴文本处理和引用结构，不能照搬其权限与删除逻辑。
- 已只读核对本机 Ollama 存在 `nomic-embed-text:latest`，模型元数据显示 768 维及 2048 上下文长度；具体模型身份应按摘要追溯，不能把 `latest` 当作固定版本。此事实不等于已经验证实际推理、中文检索质量或性能。
- Chroma 服务、Embedding 与生成模型分别配置。Java 客户端版本、Chroma 服务版本和实际协议兼容性需在后续技术设计及实现中验证；本 PRD 不锁死 collection 分区或新增 Schema。
- 模型切换导致向量不可比时需要重新处理资料，具体迁移与不可用窗口在设计阶段评估，不能混用不同模型的向量冒充可用结果。
- 不重构完整生成链路；现有取消、时限、幂等、需求保留、自动修复上限、草稿与成功版本保护继续生效。
- 现有生成追踪阶段仍在独立实施；本功能参考资料长期保留的规则不修改其 7 天追踪策略，也不将资料正文追加到普通追踪日志。
- 本轮仅文档。数据库 Schema、接口及鉴权实现方案的批准和功能验证另行处理，不因需求冻结而宣称已经获准或完成实施。

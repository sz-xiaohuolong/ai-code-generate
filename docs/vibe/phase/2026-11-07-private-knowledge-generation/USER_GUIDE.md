# 个人知识库 MVP：使用与人工验收

这次功能解决的是“每次生成都要重新粘贴接口文档和业务规则”的问题。用户把资料上传一次，后续在自己的应用中开启知识库，平台就从本人资料中找出相关片段，再据此生成代码。它服务于代码生成过程，不会自动让生成的网站变成知识问答系统。

**当前尚未达到可默认启用的状态。** 本地 `nomic-embed-text:latest` 的中文正负样本未通过相关性验证，其他本地模型的对比尚待用户决定。代码默认 `knowledge.enabled=false`。链路测试成功与资料找得准确是两回事；不能仅将开关改为 true 就声称质量验收完成。当前证据及剩余项见 [VERIFICATION.md](VERIFICATION.md)。

## 1. 实际业务流程

1. 用户进入“知识库”，上传 UTF-8 编码的 `.md` 或 `.txt`。后端从登录态取得用户身份，检查文件、份数和容量，保存本次操作及候选版本。
2. 后台把文本分成小段，调用本地 Ollama 生成向量。向量是用于计算内容相似程度的数字表示；文本超过模型窗口时继续分块，不截断。
3. Chroma 把向量和片段存进该用户专属的 collection（资料分区）。每次处理还有独立 buildId（构建批次），处理中的版本不会参与检索。写入后读回核对，全部完整才发布新版，替换失败时旧版仍可用。
4. 用户在首页或工作台开启“使用个人知识库”并发送需求。本次选择随请求固定，后台先保存参考记录头，然后让现有工具模型组织 `searchKnowledge(query)` 请求。
5. 模型只提供查询词。后端绑定当前用户和已发布版本，调用本地向量模型、检索 Chroma，再与业务数据库核对。跳过工具最多纠正一次；无资料、无命中或依赖故障都会停止。
6. 成功后把实际片段固定在本次任务内。每次代码生成、自动重生成和修复请求都会带上同一份资料；不依赖聊天窗口仍记得它。写文件和最终接受结果之前也检查是否已取得资料。
7. 用户在工作台打开“查看参考资料”，核对名称、版本和实际片段。资料命中不代表生成代码完全正确，仍应检查接口地址、字段和业务行为。
8. 来源长期保留，随应用删除。删除原文档后，新任务不能检索它，历史片段隐藏；已经生成的代码或对话内容不会自动清除。删除应用不删除个人知识库。

## 2. 本地启动条件

以下命令为待用户执行业务环境验收的步骤，不代表已经在个人业务库或外部生成模型上执行过。

### 2.1 数据库与基础服务

沿用项目 Java 21、MySQL、Redis、Node.js 和 Yarn 环境。先备份业务库，再在目标库执行本功能迁移：

```bash
mysql -u root -p ai_code_generate < sql/migrations/20261107_private_knowledge.sql
```

迁移创建六张独立 `knowledge_*` 表，可重复执行，不删除既有业务表。不要把验收目录里的临时数据库当成个人业务库。

启动带持久卷且只监听本机的 Chroma：

```bash
docker run --name ai-code-knowledge -d \
  -p 127.0.0.1:8000:8000 \
  -v ai-code-knowledge:/data \
  chromadb/chroma:1.1.0
```

如果该容器已经存在，使用 `docker start ai-code-knowledge`，不要重复创建。检查 Ollama 和 Chroma：

```bash
curl http://127.0.0.1:11434/api/tags
curl http://127.0.0.1:8000/api/v2/heartbeat
```

### 2.2 配置与模型验证

在不提交密钥的 `application-local.yml` 中参考项目配置示例设置地址、模型和容量。只有在选定模型完成中文正负样本验证后，才设置 `knowledge.enabled: true`。模型摘要、维度或分块配置变化时需要重建索引；首版没有自动模型迁移界面，不能对已发布资料直接切换配置后继续混用。

关闭 `langchain4j.open-ai.streaming-chat-model.log-requests` 和 `log-responses`。Vue 工具模型的原始请求／响应日志已在代码中关闭。向量化留在本地；查询规划和生成仍使用项目已有模型配置，相关资料片段可能发送至外部生成服务。

默认限制：单文件 2 MiB、每用户 50 份、当前资料共 20 MiB；分块 512 字符、重叠 64 字符；候选 12、最多采用 6 段及 6000 字符。检索阈值必须按模型校准，示例中的 0.65 不是合格质量结论。首期管理页支持最多 50 份，请勿将 maxDocuments 提高到 50 以上；调整文件上限时还需检查 Spring multipart 24 MB 请求总量限制和存储字段容量。

### 2.3 启动应用

```bash
./mvnw spring-boot:run
```

另开终端：

```bash
cd ai-code-frontend
yarn install
yarn dev
```

后端默认 `8123/api`，前端使用 Vite 实际显示的地址。若端口被其他项目占用，使用独立端口并核对前端请求地址和后端跨域配置。

## 3. 人工验收步骤与预期

使用两个独立浏览器会话分别登录 A、B 两个测试用户。仅使用无敏感信息的测试资料；首次真实生成会调用已配置模型，产生相应服务用量。

创建 `订单接口.md`：

```text
星海商城订单查询：GET /internal/orders。
分页参数：pageIndex、pageSize。
订单字段：orderNo、buyerName、totalAmount、status。
取消订单：POST /internal/orders/{orderNo}/cancel。
已发货订单禁止取消。资料专属标记：XH_ORDER_2026。
```

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 1 | A 打开知识库，上传测试文件 | 先显示处理中，完成后为 v1 已就绪；列表不把“已上传”等同于可检索 |
| 2 | 上传 PDF、空文件、超过 2 MiB 的文件 | 明确拒绝，不截断、不新增可用版本 |
| 3 | B 打开知识库；尝试使用 A 的文档 ID 替换、删除或读取来源 | 看不到 A 的列表，越权请求被拒绝且无名称／正文泄漏；管理员非所有者同样拒绝 |
| 4 | A 在首页开启知识库，要求生成星海商城订单管理页 | 首次生成带上选择；后台先检索后生成；工作台可查看参考片段 |
| 5 | 核对生成代码和浏览器行为 | 查询地址、分页参数、字段及取消地址与资料一致；已发货订单不能取消。不以生成成功提示代替检查 |
| 6 | 在工作台继续修改页面，然后刷新或切换应用 | 同页沿用开关；刷新／切应用后下一次请求关闭；已经发出的任务不改变选择 |
| 7 | 开启知识库提出无关需求，例如太阳系科普页；对照多条无关负例 | 没有相关资料时停止，不进入产物生成；若错误命中则质量验收失败，应重新评估模型／阈值 |
| 8 | 暂停 Ollama 或 Chroma 后开启知识库生成 | 明确依赖故障，上次成功版本保留；关闭后新发普通任务可沿用普通生成 |
| 9 | 将接口改为 `/v2/orders`，显式替换 | 处理中仍用 v1；故障时 v1 不受影响；恢复并重试成功后新任务只检索 v2 |
| 10 | 同名再上传一次 | 新增独立文档，不自动覆盖；网络重试同一提交不重复启动处理 |
| 11 | 任务取得片段后替换或删除文档 | 当前任务保留原快照完成；新任务不能取得已删内容；历史来源仍留名称版本，片段隐藏 |
| 12 | 删除应用，再检查个人库 | 应用来源不可访问并被清理，个人库仍在；另一个本人的应用可以继续使用资料 |
| 13 | 标准／工作流分别测试 HTML、多文件、Vue | 六种组合都遵循先检索再生成；自动修复仍参考同一片段。记录每组实际生成结果，不以入口分流测试代替真实生成 |
| 14 | 在限定测试环境检查模型网络请求与日志 | Embedding 请求仅去配置的本地 Ollama；资料不进入普通请求日志、公开静态文件或普通 SSE 事件 |

多文件与 Vue 类型由应用已有路由决定。验收时先在应用详情确认类型；若无法稳定命中所需类型，应在隔离测试库预设对应应用，不能修改真实应用类型来绕过现有规则。

## 4. 故障排查与恢复

- 无可用资料：等待处理完成，或在管理页重新处理失败版本。
- 无命中：核对资料和需求语境、查看中文正负样本表现；不要仅降低阈值让所有请求通过。
- 模型／索引不可用：核对服务地址、模型名称及健康检查，恢复后用新请求重试失败处理。
- 参考记录不完整：仍能看到长期记录头；不能把它解释成未开启知识库或补造片段。
- 关闭功能：设 `knowledge.enabled=false`，停止新知识任务，保留表和数据卷。不要删除数据卷作为回退手段。

## 5. 开发中值得保留的做法

先把“无命中如何处理、资料何时固定、删除后保留什么”写成可检查的产品规则，再设计接口和存储。模型负责组织查询，权限、调用顺序和成功条件由程序执行。版本发布采用“先完成新索引、再切换指针”，避免替换失败损坏旧资料。最后分别验证事务、向量服务、生成请求和页面，避免把某一层通过误当成整个功能已经可用。

## 产品行为

### REQ-01 模式选择与保存

顶部提供“标准模式／工作流模式”选择，标注“新建默认模式”。默认标准模式，在当前浏览器记住选择。首页输入区同步说明当前模式。新建应用时把模式保存到应用记录；刷新、换浏览器及打开历史应用均以服务端记录为准。应用创建后不能修改模式。未指定模式的旧客户端与历史应用均兼容为标准模式；未知模式明确拒绝。

### REQ-02 两种执行方式

标准模式保留现有直接生成和对话迭代。工作流模式复用素材收集、提示增强、代码生成、质检重试与按需构建。两种模式与 `codeGenType` 独立，均支持 HTML、多文件、Vue。后续对话复用应用已有代码类型，避免重新路由造成产物目录漂移。

### REQ-03 统一工作台

工作台只读展示应用模式。两种模式共用应用聊天入口、登录与归属校验、限流及既有下载、预览、部署能力。前端请求不能改变应用模式或指定执行用户。独立工作流演示接口也必须校验登录及应用归属，避免形成旁路。

### REQ-04 真实过程与结束状态

工作流展示每个节点的进行中、完成、检查未通过、跳过检查与失败状态，并透传生成文本和工具活动。质检最多重新生成两次；无错误列表的失败结果也受相同上限约束。质检服务异常允许降级，但必须显示“已跳过检查”。生成失败、质检重试耗尽或构建失败均显示失败，不展示成功预览。正常结束才展示新产物。Vue 在一轮工作流中通过质检后构建一次。

### REQ-05 历史与兼容

保留既有 SSE 外层数据包装和结束事件。工作流增加可识别的进度消息。业务历史记录原始用户输入及本轮最终回复/结果；素材增强和内部重试不产生新的用户对话。刷新可恢复对话与应用模式，节点运行进度只负责本轮实时展示。

## 验收标准

| AC | 可测行为 |
|---|---|
| AC-01 | 默认标准模式；切换后首页同步，刷新保留浏览器偏好；新建请求携带所选模式 |
| AC-02 | 两种模式保存到数据库；旧请求/历史记录兼容标准；无效模式被拒绝；更新接口不能改模式 |
| AC-03 | 顶部切换不影响旧应用；工作台展示服务端模式；后端按记录选择执行链路 |
| AC-04 | 工作流按真实节点展示进度与内容；支持质检回环、跳过检查、生成/构建失败 |
| AC-05 | 后续对话保持代码类型；HTML/多文件跳过构建，Vue 质检后只构建一次 |
| AC-06 | 工作流只保存一次原始用户输入，历史恢复正确；其他用户无法生成或调用演示接口操作该应用 |
| AC-07 | 两种模式生成结果均可按现有规则预览、下载和部署；相关后端测试及前端构建通过 |

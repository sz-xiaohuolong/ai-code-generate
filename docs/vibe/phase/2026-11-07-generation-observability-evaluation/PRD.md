为应用所有者提供可查询的生成过程记录，为维护者提供可重复执行的固定用例评测。正常生成仍按现有交付规则完成；独立评测用于判断固定场景下的质量与变化，不新增发布拦截。

## 1. 产品概述与背景

现有系统提供标准／工作流两种生成模式，以及 HTML／多文件／Vue 三种代码类型。已有后台任务、幂等、取消、自动修复、成功版本保护、部分模型用量统计和浏览器运行检查。

当前记录主要回答“正在做什么”和“最终是否交付成功”。同名阶段会覆盖前一次记录，模型调用缺少独立的耗时、结束原因与完整关联；创建应用的路由发生在生成任务之前。浏览器检查主要证明页面可运行，不能证明按钮、表单和筛选满足需求。

本次成功定义：所有者能够定位一次创建或生成中的阶段、调用及失败；维护者能够用同一组版本化样本重复运行，并区分工程回归、真实模型质量、记录缺失和环境故障。背景事实见设计第 1 节；原生成行为继续遵循 [p0-reliability/SPEC.md](../../phase/2026-10-18-p0-reliability/SPEC.md)，不改写其历史验收。

## 2. 目标与非目标

- **追踪目标**：覆盖创建路由与回退、两种模式中的生成／检查／工具／修复／构建／预览；保留每次步骤与调用，不仅保存最新阶段。
- **评测目标**：维护 24 条固定用例，18 条开发集、6 条留出集；提供命令入口、逐用例证据和对比报告。
- **交付边界**：工作台展示追踪；评测由维护者在本地或自部署环境运行，报告作为本地文件导出。
- **非目标**：通用任意需求评分、评测管理后台、额外模型评分、评测驱动的自动修复、发布质量门禁、RAG、金额估算、监控大屏、第三方观测云平台。
- **既有行为**：平台已有 AI 质检和自动修复继续执行；它们的结果是被观测对象，不取代独立业务断言。

## 3. 目标用户与使用场景

| 用户 | 入口与权限 | 典型结果 |
|---|---|---|
| 应用所有者 | 工作台的应用生成记录与本次过程入口 | 查看自己的调用与步骤，判断失败位置、修复次数和用量缺口 |
| 发起创建的登录用户 | 创建响应中的请求编号及对应诊断入口 | 即使没有生成 appId，也能查询自己的创建路由失败记录 |
| 维护者 | 显式执行本地评测命令，持有对应环境配置 | 选择数据集、配置与运行模式，导出 JSON／HTML 结果并比较两次实验 |

管理员身份不扩大任务追踪读取权限；继续沿用任务接口的“仅所有者”规则。维护者命令不意味着普通网页用户获得服务器执行权限。

## 5. 核心功能与验收

### 5.1 REQ-01：完整关联一次执行

登录用户创建应用时先得到创建请求编号；无论路由成功、回退或失败，都能据此定位已记录的过程。创建成功后记录关联应用；之后每次生成拥有独立任务追踪。应用生命周期不是一个持续增长的单次追踪。

生成追踪覆盖真实发生的阶段。一次初始生成、自动重生成、修复模型请求或同名图节点重入必须有独立记录。记录尝试顺序、父子关系、开始／结束、结果和可得的模型结束原因；供应商未返回的信息标记未知。逻辑调用与供应商内部重试的统计口径必须明确，不能冒充可观测的物理请求数。

任务创建／订阅／取消仍由原任务服务决定。重复提交返回原任务，不重复启动生成追踪；页面断线不会结束后台追踪。取消、超时、服务中断与业务失败分别呈现。只有真实终态和已核验产物关联才能表示任务完成，不根据模型流结束提前写成功。

| AC | 给定—当—则 | 检查入口 |
|---|---|---|
| AC-01 | 给定创建路由主模型失败且回退成功，当创建完成，则同一创建记录包含两次独立调用并关联新应用；全部失败时仍有请求编号，appId 可为空 | 创建 API、创建诊断查询、受控路由模型 |
| AC-02 | 给定同一需求经历生成、构建失败、修复与成功交付，当查看任务过程，则原失败和修复后成功同时存在并关联相同任务及最终产物 | 任务 API、追踪详情、构建修复夹具 |
| AC-03 | 给定幂等重试或 SSE 重连，当重复请求，则复用原任务与追踪；显式停止时分别看到停止请求与最终取消，不能把断连当取消 | 任务创建、订阅、停止与追踪接口 |
| AC-04 | 给定进程中断导致记录未闭合，当重新查询，则显示记录中断／结果未知或有证据的任务终态；不得补造耗时、用量和成功产物 | 故障恢复、记录完整性、原任务状态 |

### 5.2 REQ-02：查看过程、用量与缺口

工作台提供应用级历史列表和本次过程快捷入口。详情按步骤展示层级、重试、模型／Prompt 版本、耗时、用量、工具名、相对文件路径和脱敏错误。历史查询不依赖 Redis 任务快照仍存在，也不依赖聊天消息一定携带 taskId。

每个实际返回的输入／输出 Token 分项记录，缺失字段保持未知；汇总同时展示已知用量、调用数量及上报覆盖率。部分上报不能显示为完整总量。首期不折算金额，也不推断供应商实际账单或取消后的计费。

追踪写入或展示失败时正常生成继续；界面区分“生成失败”“追踪不完整”“追踪暂不可用”。能获得局部证据时展示局部结果；未获得的记录不由聊天文本猜补。

| AC | 给定—当—则 | 检查入口 |
|---|---|---|
| AC-05 | 给定 A、B 两个用户，当 B 请求 A 的应用、任务或创建请求追踪，则服务端拒绝；管理员身份也不自动放行 | Session 鉴权、列表与详情 API |
| AC-06 | 给定两次调用只有一次返回用量，当查看报告，则展示已知值和覆盖情况，另一调用为未知；不得显示“完整合计” | 模型响应夹具、详情与报告 |
| AC-07 | 给定追踪数据库／队列故障，当生成仍能通过原交付检查，则生成仍成功，追踪显示不完整或不可用；恢复后不把丢失部分自动标完整 | 故障注入、任务结果、追踪详情 |
| AC-08 | 给定任务快照超过现有 24 小时而追踪未超过 7 天，当所有者查询应用记录，则仍可查看追踪；不能借此恢复执行或延长幂等期 | 可控时间、Redis 过期、追踪存储 |

### 5.3 REQ-03：元数据、保留与删除

日常追踪不额外保存完整用户输入、模型回复、文件正文或推理正文；已有聊天记录规则不变。Prompt 版本指生成所用模板／配置版本，不等于把用户原文存入追踪。错误内容使用分类与经过白名单处理的诊断，不能直接转存供应商响应或堆栈中的秘密。

追踪保留期为创建记录后 7×24 小时，查询时执行过期判断。应用删除后立即拒绝其关联追踪查询，并清理关联记录；物理清理可在后台重试，延迟不恢复可见性。没有 appId 的创建失败记录按发起用户和自身保留期管理。以上为新增追踪数据的规则，不改变既有聊天、任务快照和代码产物规则。

appId 为空不等于创建失败：若应用可能已经保存、但追踪关联尚未确认或已经丢失，则仅提示记录不可用，不展示该记录的诊断详情。不能利用这一异常窗口绕过应用删除后的访问限制。

评测使用专门编写的非敏感样本；其输入、产物和失败证据写入维护者指定的本地导出目录。报告不纳入追踪自动过期，也不会随应用删除而自动删除；维护者自行管理。默认不公开托管，不上传观测云平台。

| AC | 给定—当—则 | 检查入口 |
|---|---|---|
| AC-09 | 给定输入、工具返回或供应商错误包含测试密钥与绝对路径，当记录追踪，则存储与 API 中没有原文秘密、完整正文和宿主绝对路径 | 注入标记、存储查询、API 响应 |
| AC-10 | 给定记录已过 7 天或关联应用已删除，当直接访问追踪编号，则不可查询；清理失败重试期间和迟到写入也不能恢复访问；创建成功但关联丢失时不得按无应用的创建失败展示详情 | 可控时间、删除服务、后台清理、迟到回调、创建关联丢失夹具 |
| AC-11 | 给定受控评测已导出报告，当关联测试应用删除或在线追踪过期，则导出结果仍可由维护者在本地读取，不发生外部上传 | 导出目录与网络调用检查 |

### 5.4 REQ-04：固定数据集与两种运行模式

数据集共 24 条人工维护用例：18 条开发集用于调整，6 条留出集用于独立检查。覆盖标准／工作流、HTML／多文件／Vue、新建／修改与故障／取消。各用例包含稳定编号、输入、初始状态、验收规格、适用模式和版本；具体样本分配见设计第 4.4 节。

默认受控模式使用确定性模型及外部工具夹具验证工程链路。真实模型模式必须显式选择并提供最大模型调用数、总时限；首期没有额外模型评分。工程故障用例与真实质量用例分组，受控结果不能写成真实生成成功率。

每次运行固定数据集、验收器、代码、Prompt、模型配置和环境信息；修改场景还固定初始产物。运行使用独立评测环境与应用，不能修改真实用户应用或发布目录。命令不是现有全量 Maven 测试的别名；默认执行不能隐式调用原测试中的付费模型。

| AC | 给定—当—则 | 检查入口 |
|---|---|---|
| AC-12 | 给定版本化数据集，当校验清单，则共有 24 个唯一编号、18/6 分组及可定位的验收规则；未支持的场景明确拒绝 | 数据集校验器与版本摘要 |
| AC-13 | 给定默认受控运行，当完成评测，则没有真实模型／外部业务工具调用，报告明确标记受控回归 | 评测命令、模型适配器、外部调用探针 |
| AC-14 | 给定真实模式缺少显式选择或预算参数，当启动，则在模型调用前拒绝；达到调用上限或总时限后不再发起下一次调用 | 命令参数、计数器、时钟、供应商适配器 |
| AC-15 | 给定一次修改用例和真实用户已有应用，当运行评测，则仅变更隔离测试应用，报告记录初始产物与实际输出版本 | 评测隔离配置、工作区与应用记录 |

### 5.5 REQ-05：分层质量判断

每个用例独立记录生成结果，以及构建、页面加载、业务断言结果。无需构建的 HTML／多文件维度标记不适用，不用“构建通过”抬高统计。业务断言使用人维护的点击、输入、提交、筛选与状态检查，生成模型无权改写。

用户行为不符合预期属于质量失败；缺少浏览器、受控接口不可用或评测器异常属于环境／执行错误；取消和未执行单列。工程用例期待取消时，可以出现“任务取消、工程回归通过”，但不能计作真实模型生成成功。

| AC | 给定—当—则 | 检查入口 |
|---|---|---|
| AC-16 | 给定能构建和打开但按钮无效的产物，当运行对应业务断言，则业务维度失败且保存失败步骤和证据 | 浏览器验收器、故障产物 |
| AC-17 | 给定浏览器环境不可用或任务被取消，当运行，则分别记录环境错误或取消；不能计为通过，也不能静默排除出总样本数 | 环境预检、取消夹具、报告 |
| AC-18 | 给定独立评测判断失败，当检查正常应用的任务、成功版本及部署结果，则不发生评测新增的拦截、修复或状态改写 | 正常任务状态、成功指针、发布路径 |

### 5.6 REQ-06：报告、比较与完成语义

导出 JSON 作为机器可读事实，HTML 展示逐用例结果、失败证据、耗时、用量与覆盖情况。单次运行有稳定编号，每次重跑产生新运行，原报告不被覆盖。

报告区分计划、已执行、通过、失败、环境错误、取消、跳过及追踪缺失数量；只在配置和样本可比时给出质量变化。追踪缺失的样本可展示可证实的业务断言结果，但不进入完整调用／耗时／用量对比集合，且必须说明排除原因。

正常报告中的质量失败与“报告本身未完整生成”必须能通过命令退出结果区分。必要报告或证据写入失败时返回未完整完成；用户不能把空报告当作零失败。首期不承诺成功率提升数值、稳定 P95 或金额节省。

| AC | 给定—当—则 | 检查入口 |
|---|---|---|
| AC-19 | 给定相同版本与配置，当重复运行，则每次有独立运行编号、逐用例结果及可追溯产物；差异真实保留，不要求随机模型输出逐字相同 | 命令、运行清单、报告比较器 |
| AC-20 | 给定样本／验收器版本不同或用量缺失，当比较，则显示不可比项和覆盖缺口，不能输出误导性提升比例 | 对比报告、用量夹具 |
| AC-21 | 给定输出目录不可写、关键截图或报告写入失败，当运行结束，则命令明确非完整完成，已有结果保留但不伪造完整报告 | 文件故障注入、退出码、完成清单 |

## 6. 交互与界面状态

| 入口 | 空状态 | 加载状态 | 错误状态 | 大量／超长内容 |
|---|---|---|---|---|
| 工作台生成记录 | 显示尚无可查询记录；不回填历史 | 保留当前工作台操作，独立加载记录 | 区分无权、过期、暂不可用，提供重新查询 | 分页加载；长列表不一次性下载全部步骤 |
| 本次追踪详情 | 有任务但未取得记录时显示等待／不可用，不显示成功 | 展示已记录步骤和运行中状态 | 已有步骤保留，缺口明确标注 | 步骤详情展开；诊断截断须标记 |
| 创建失败诊断 | 没有已持久化记录时仍显示请求编号 | 按编号查询 | 保留原创建错误，诊断故障不替换原错误 | 仅展示脱敏字段 |
| 本地 HTML 报告 | 零个可执行用例视为配置错误 | 无在线加载要求，读取已导出结果 | 缺证据明确提示，并保留逐项结果 | 长表可筛选，路径和内容作为文本安全显示 |

## 7. 限制条件与跨功能边界

- 现有 REST／SSE 响应与任务幂等、24 小时保留、取消、总预算和成功版本保护继续有效；新增字段或响应头采用兼容方式。
- 追踪持久化不能参与正常应用生成的成功判定，也不能取得对任务状态的写入权。
- 追踪数据与独立评测报告具有不同生命周期；7 天保留不能被解释为持久化恢复执行能力。
- 真实评测的调用上限限制发起次数，不保证供应商金额硬封顶；已发出的请求可能产生取消后的消费。
- 需求确认本身不证明运行性能或模型效果；新增 SDK 的依赖解析、隔离存储迁移和实际浏览器路径的实施验证由 [验收记录](VERIFICATION.md) 维护。

# 平台首页与工作台 UI 美化方案

推荐采用「浅色创作入口 + 专注式双栏工作台」：沿用蓝色品牌、Vue 与 Ant Design Vue，重点调整操作层级、内容密度、主题一致性和移动端组织。首页帮助用户开始或继续创作；工作台让对话、生成状态和作品预览各有固定位置。

- 日期：2026-11-07。
- 状态：`IMPLEMENTED`；2026-11-08 用户确认按推荐方案实施，范围冻结为首页、生成工作台及三类管理员页面。
- 已确认范围：用户明确选择优先美化平台自身的首页和工作台。
- 批准方向：首页参考 v0／Bolt，控制台采用 Cobalt 浅色视觉，管理页采用 Ink 列表语言与 Almanac 表格层级。深色跟随系统，保留已有业务功能。
- 产品依据：[PRODUCT.md](../../../../PRODUCT.md)、[AGENTS.md](../../../../AGENTS.md)。
- 工作流依据：用户提供的「前端设计六步工作流」。
- 当前产出：已完成前端实施与桌面／手机／深色截图对照；现有测试、构建和 26 项受控浏览器验收通过，独立复审与同步状态见 [验收记录](VERIFICATION.md)。历史调研段落保留当时的核验范围。

## 1. 结论与改造范围

### 1.1 两个候选方向

| 方向 | 视觉与结构 | 收益 | 成本与适用条件 |
|---|---|---|---|
| A：克制的创作工具，推荐 | 中性浅底、蓝色操作焦点、精简输入区；工作台保留左右分栏 | 与现有代码和品牌接近，优先改善核心任务效率 | 主要是布局、主题和状态呈现调整；适合当前开发者与 Web 创作者 |
| B：暗色品牌展示 | 深色首屏、大面积品牌光效、作品展示更突出 | 品牌表现更强，适合以拉新传播为主的页面 | 需要更多品牌素材和主题校验；如果后续单独建设营销官网，可重新考虑 |

选择 A 的理由：当前产品的价值是完成生成、检查和迭代，主界面应把面积留给输入与作品。不会把“去 AI 味”理解成禁止蓝色、居中排版或规则网格；这些形式是否合适取决于任务。

### 1.2 本次拟改范围

1. 首页：全局导航中的新建模式入口、标题与输入区、示例、我的作品、精选案例及相关状态。
2. 工作台：工具栏、对话与预览分栏、生成状态、生成记录入口、移动端布局。
3. 共享基础：颜色与主题映射、间距、按钮、输入、焦点、作品卡片。
4. 用户、应用与对话管理页：统一管理导航、筛选工具栏、表格层级、详情与行操作；登录和设置页只做共享样式回归。

既有模式、权限、REST/SSE、取消、旧成功版本保留、下载和部署语义均作为约束。生成出来的网站风格、模型提示词体系、知识库功能与后端架构不属于本次美化范围。

### 2.2 帖子的采用方式

原站正文需要登录，本轮通过作者 `liyupi/ai-guide` 公开仓库读取同篇全文，未绕过登录限制。七类方法在本项目中的取舍如下。

| 帖子方法 | 本项目采用方式 |
|---|---|
| 参考真实网站 | 选两个直接同类产品，按“输入入口、预览修改、作品浏览”分别参考 |
| 设计优先 | 先确认本方案的布局和交互，再编码；不以大规模实现代替设计决策 |
| 丰富图片 | 作品卡优先使用实际应用封面；没有封面明确显示“暂无预览”，不用随机照片暗示作品效果 |
| 明确提示词约束 | 写清主要任务、层级、状态与禁用的无效装饰；不照搬“禁止纯色／必须不对称” |
| Agent Skills | 使用已有 Impeccable 设计能力；技能选用服从当前任务，不重复安装相似技能 |
| 特色组件 | 延续 Ant Design Vue，针对视觉做统一适配；不为动效迁移组件体系 |
| 自主配色 | 沿用蓝色品牌，用语义变量建立深浅配对，保留错误、警告和成功各自含义 |

文章对模型为何偏好特定配色的解释不作为本项目技术事实。蓝色、系统字体、纯色背景与常规网格本身不是缺陷；本次要解决的是默认样式缺乏统一、操作入口分散和状态表达不清。

### 2.4 控制台追加调研：Hallmark 主题与真实工作台

用户认可首页参考方向后，本轮按要求继续调研控制台。此处更新控制台的参考依据，首页保持原方向；以下均为待选方案，不触发实施。

## 3. 推荐页面方案

以下尺寸、文案与交互均为建议，等待设计确认，不作为已经批准的产品变化。

### 3.1 首页：开始创作与继续作品

首屏建议文案：标题“把想法，变成可运行的网页”；说明“描述需求，生成后即可预览、修改和部署。”去掉“新一代”等不能帮助操作的徽章。

```text
品牌                 首页  关于                    账户

                 把想法，变成可运行的网页
                 描述需求，生成后即可预览、修改和部署。

        ┌─────────────────────────────────────────┐
        │ 描述你想做的网站                         │
        │ 例如：一个展示作品、介绍和联系方式的个人主页 │
        │                                         │
        ├─────────────────────────────────────────┤
        │ 标准模式 / 工作流模式       [开始生成 →]   │
        └─────────────────────────────────────────┘
          博客网站    企业官网    商品页    作品集

我的作品                                      搜索
真实封面与作品标题        真实封面与作品标题      …

精选案例                                      搜索
真实应用效果             真实应用效果           …
```

建议细节：

- 内容区最大宽度 1200px，输入区最大宽度 760px；桌面首屏上内边距约 40px，手机约 28px，最终以目标视口截图确认。
- 标题桌面 36px、手机 28px，正文 14–16px；减少负字距，优先照顾中文阅读。
- 模式切换与创建按钮放在同一输入组件底栏。保留已有默认模式存储及“仅影响新建”的含义，短说明随选择变化。
- “开始生成”作为此区域唯一填充色按钮。提交期间显示“正在创建”，防止重复提交；保留现有 800 字限制和创建错误诊断。
- 示例只填入输入框，不自动提交；已有示例的行为不变。文案优化不能引入产品不支持的生成能力承诺。
- 我的作品与精选案例保留两个分区及现有独立搜索、分页，不新增排序字段或后台聚合接口。
- 作品卡使用 16:10 封面、两行内标题、更新时间、类型与主要操作。复用已有 `app.cover` 和失败回退逻辑；无封面时显示克制占位与明确说明。
- 已登录但无作品、未登录、搜索无结果、请求失败分别呈现不同文字。未登录可指引登录；请求失败保留查询并提供重新加载，不冒充“暂无作品”。

### 3.2 工作台：对话推进，预览为主

```text
返回首页  应用名称  固定模式              生成记录  更多  [部署上线]
─────────────────────────────────────────────────────────────
 当前生成阶段与连接状态                                 停止生成
──────────────────────┬──────────────────────────────────────
 对话                  │ 预览 / 代码     桌面 平板 手机  刷新
                       │
 用户需求              │
 AI 回复与执行摘要      │          实际应用预览
 详细工具信息可展开     │
                       │
──────────────────────│
 描述修改需求          │
 已选元素（如有）  发送 │
──────────────────────┴──────────────────────────────────────
```

- 继续使用现有分栏与拖拽能力。桌面对话栏初始约 36%，设置建议下限 340px；预览取得余下空间，不叠加多层装饰外壳。
- 精简工作台中的全局导航，将返回首页、账户与应用工具栏组合；保留原有管理和账户入口的可达性，不修改路由权限。
- “预览／代码”和视口切换靠近右侧预览区域；部署为主要操作，下载和详情进入“更多”。“生成记录”保留文字入口，避免诊断能力被完全隐藏。
- 顶部状态条只显示真实阶段、必要的连接提示和停止动作。不根据经过时间捏造百分比。
- 对话呈现需求和回复，工具调用详情折叠；不得在重组时丢失错误、降级、重试或取消信息。
- 桌面生成记录使用右侧覆盖抽屉，建议宽 520px；小屏使用全屏面板。抽屉内部复用 `GenerationTracePanel`，保留历史、分页、详情和查询状态。
- 打开记录不改变主工作区高度，不重置对话滚动或输入；关闭后恢复焦点。记录只读属性、所有者权限、追踪不完整提示等语义保持。
- 既有可视化点选编辑继续使用原协议，新增的仅是更明确的入口、选中反馈和退出状态；不扩展成属性编辑平台。

### 3.3 响应式策略

| 宽度 | 首页 | 工作台 |
|---|---|---|
| ≥1280px | 输入区居中，作品三列，内容最大宽度受控 | 可拖拽双栏；工具分组完整显示 |
| 768–1279px | 输入区收窄，作品两列 | 960–1279px 优先双栏并收起次要按钮；低于 960px 使用分区切换 |
| <768px | 两侧 16px，作品单列，示例自然换行 | 对话／预览／代码切换，诊断全屏，主要触控目标建议至少 44px |

小屏分区切换保留输入、对话滚动、任务订阅和预览状态，不因隐藏面板而重新发起生成或重复加载。软键盘弹出时输入及发送操作可达。全局不允许意外横向滚动，代码和真正需要横向浏览的内容在自身区域滚动。

## 4. 设计规范与主题

### 4.1 建议 Design Tokens

延续现有 `--ui-*` 命名，避免创建第二套设计系统。以下为候选基线，深浅主题仍需逐状态校验。

| 语义 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| 页面底色 `--ui-shell` | `#F8FAFC` | `#0B1020` | 页面与预览外部空间 |
| 组件表面 `--ui-surface` | `#FFFFFF` | `#131B2B` | 输入、抽屉、菜单 |
| 次级表面 `--ui-surface-muted` | `#F1F5F9` | `#1D293B` | 工具栏、悬停与分组 |
| 主文字 `--ui-ink` | `#0F172A` | `#F1F5F9` | 标题、正文 |
| 次文字 `--ui-ink-soft` | `#475569` | `#CBD5E1` | 描述、辅助信息 |
| 分隔线 `--ui-line` | `#E2E8F0` | `#334155` | 表面分界，不单独承担输入边界或焦点识别 |
| 品牌链接 `--ui-accent` | `#2563EB` | `#60A5FA` | 链接、选中、焦点 |
| 主按钮背景 | `#2563EB` | `#2563EB` | 与白色按钮文字配对，不直接复用深色链接色 |

- 状态色：浅色成功 `#15803D`、警告 `#B45309`、失败 `#B91C1C`；深色建议对应 `#4ADE80`、`#FBBF24`、`#F87171`。状态必须同时有文字或图标。
- 字体：保留系统中文字体栈；代码与编号使用现有等宽字体。不为风格增加字体下载依赖。
- 字阶：12 / 14 / 16 / 20 / 28 / 36px；正文行高约 1.6，工具标签约 1.4。12px 仅用于次要元信息。
- 间距：4 / 8 / 12 / 16 / 24 / 32 / 48px；同级组件使用相同节奏。
- 圆角：控件 8px、输入容器和作品卡 12px、抽屉按贴边结构处理；避免所有组件都做胶囊。
- 阴影：主要用于浮层和输入焦点；作品卡优先依靠边框及背景分层。
- 动效：建议 120–180ms 的颜色和透明度反馈；生成状态用轻量指示；减少动态偏好下取消非必要动画。工具栏按钮不普遍上下漂移。
- 图标：沿用 `@ant-design/icons-vue`，统一尺寸与视觉重量；功能入口不使用 Emoji。

### 4.2 主题一致性是首要修复项

目前 `base.css` 响应系统深色，`App.vue` 中 Ant Design 主题仍为固定浅色值，导航和首页还存在白色硬编码。本轮截图已看到导航文字变浅、背景仍浅和部分辅助文本难以辨识。

建议让系统主题成为当前唯一有效来源：同一主题状态同时驱动 CSS 语义变量和 Ant Design 主题配置。颜色数值统一维护，组件不能自行判断另一套主题；清理首页、导航、菜单、输入、抽屉中的不匹配背景。已有显式主题属性若实际有调用，应纳入同一优先级规则；本阶段不新增主题设置产品入口。

浅色首屏先确定布局，但交付必须覆盖深浅主题，不能只为浅色截图优化。

## 5. 关键状态与业务约束

| 场景 | 页面反馈与可用操作 | 必须保持 |
|---|---|---|
| 创建中 | 创建按钮忙碌，输入内容保留 | 不重复提交，不改变模式归属 |
| 创建失败 | 输入附近错误、重试入口及已有诊断入口 | 原需求与请求编号保留 |
| 作品加载 | 维持卡片区域尺寸的占位 | 加载、空、失败不能共用一个空状态 |
| 生成中 | 真实阶段、流式回复、停止入口 | 有旧成功版本时继续展示，并标识其来源 |
| 连接中断 | “连接恢复中，后台任务继续执行”等符合当前任务状态的提示 | 不因为断线重新创建任务 |
| 停止中／已取消 | 按真实状态禁用重复停止或允许下一轮输入 | 不显示生成成功，不移除旧成功版本 |
| 生成失败 | 明确失败阶段、可查看记录；恢复操作沿用当前能力 | 无成功产物不能伪装预览完成 |
| 追踪缺失／不完整 | 保留原提示，未知用量显示未知 | 不从部分记录推断完整调用量或成功率 |
| 部署／下载 | 各自忙碌态与结果反馈 | 沿用现有权限、可用产物和错误判断 |

这些是视觉改造需保持或准确呈现的条件，不意味着本轮已重新验证所有后台状态。
